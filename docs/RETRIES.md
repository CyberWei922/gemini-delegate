# 快速恢复与 GPT 接手

1.6.0 优先减少等待：刚启动的短暂连接失败快速重试，任务处理中断直接作废并交回主智能体。

| 设置 | 默认与含义 |
| --- | --- |
| `max_attempts` | 3，含首次；可设 1–5，1 表示禁用重试 |
| `timeout_seconds` | 40 秒，范围 15–600；执行开始后，读取、槽等待、退避和所有尝试共用 |
| `attempt_timeout_seconds` | 固定 25 秒，不逐次增加；可显式指定 15–600 秒 |

调用有最多约 2 秒的进程清理余量，仍受剩余总预算限制。执行线程尚未启动前的排队时间单独计入等待，
不属于执行预算。成功结果无需等待原生会话改名。

## 哪些情况重试

必须同时满足：AGY 明确报告资格检查或头像读取等推理前阶段的临时网络错误；
本次调用在 15 秒内结束；没有响应、正用量或会话进展的相反证据。
例如资格检查中的 EOF、连接重置或 TLS 超时。重试前分别等待 0.25、0.5 秒，期间释放模型槽且可取消。
最多尝试 3 次并不保证一定发出 3 次调用：总预算不足时提前停止。

## 哪些情况直接作废

- 已有响应、用量、原生会话编号，或明确处于生成阶段时发生的中断、超时或 EOF。
- 无法确认阶段的硬超时或静默断开。AGY 的 JSON 输出可能到结束时才打印，没有输出不能证明没有开始。
- 空结果、JSON／格式校验失败、权限拒绝、认证或额度错误。

这些情况不自动重放，部分内容不能应用到源文件。记录仍保留失败阶段、尝试次数、原生编号与已报告用量，
用量缺失是未知。最终 `failed` 且 `handoff.ready: true` 后，由当前 GPT 主智能体接手原任务；
插件不会另开 GPT 代理，也不要自动新开一轮 Gemini 重试。用户取消不触发接手。

各次调用使用同一输入快照、独立上下文，不续接上一次模型问答。任务仍在 `retrying`、`running`、
`waiting_for_agy` 时读取同一个 ID，继续可独立进行的工作，避免重复提交。

## 中文名称和较大后台任务

成功结果立即返回；macOS/Linux 的官方 `/rename` 在独立后台元数据助手中处理，使用自己的锁和
30 秒期限，不占两个模型执行槽、不增加模型问答。初始 `native_title.status: pending` 表示尚未完成，
后续查询合并真实状态；只有 `set` 才能宣称改名成功。失败任务不等待改名，Windows 仍报告 `unsupported`。

简单任务保持默认短期限，大文件应先拆分。确实需要较长独立后台任务时，明确设置总预算和固定单次上限，
不会改变“处理中断不重放”的规则。

```json
{
  "title": "整理名称",
  "workspace": "/absolute/project",
  "instruction": "提取唯一名称，保持顺序",
  "context": "小明、小红、小明"
}
```

兼容客户端可显式设置 `--max-attempts 3 --timeout 40 --attempt-timeout 25`。
升级后核对 `gemini_status.default_retry_policy`。旧 MCP 连接未刷新时使用新版兼容客户端，
不要中断其他对话；安装文件更新不等于旧连接已经热加载。
