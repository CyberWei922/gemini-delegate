# 自动重试与 GPT 接手

1.5.0 默认先让 Gemini 自动尝试最多 3 次（首次加 2 次重试），失败后再由主智能体接手。
整个任务默认 300 秒，重试不会重新计时。正在重试时，GPT 可以继续其他独立工作。

| 设置 | 默认与含义 |
| --- | --- |
| `max_attempts` | 3，含首次；可设 1–5，1 表示禁用自动重试 |
| `timeout_seconds` | 300 秒，范围 15–600；包含读取、槽等待、退避、模型尝试和改名 |
| `attempt_timeout_seconds` | 自动安排，首次最多 60 秒；可显式指定 15–600 秒 |

默认 300 秒时，三次模型预算约为 60、90、120 秒，另有最多约 2 秒的进程清理余量。
重试前分别等待 1、2 秒，等待期间释放并发槽，也能立即取消。
短总时限会缩小自动预算；长文件任务可用总时限 600 秒、首次 120 秒。
显式单次模式在未指定首次上限时使用剩余总时限。

会自动重试的情况：模型超时、空结果、JSON 或结果校验失败，以及已识别的临时
网络／服务错误，例如 EOF、连接重置、502/503/504。
登录、权限和额度等问题直接报告，不用重复调用掩盖需要处理的原因。
如果总时限已用尽，或无法给超时后的下一次调用安排更长预算，会提前停止，
所以“最多 3 次”不保证在每一种失败下都发出 3 次调用。

每次仍然是独立的 AGY 模型调用，不续接上一尝试的上下文。重试使用同一份私有输入快照，
不重新读取可能已经变化的源文件。每次尝试的状态、错误、原生会话编号和可用用量分别保留；
未报告用量保持未知。为避免改名拖慢重试，中间失败尝试的原生改名标为 `skipped`，
成功结果或最终失败才在剩余预算内处理改名。

读取同一个任务 ID 的结果：`retrying`、`running`、`waiting_for_agy` 都不是最终失败。
主智能体应继续等待，避免另开重复任务。最终 `failed` 的 `handoff.ready` 为 true 时，
主智能体依据原任务接手或说明阻碍，不再自动新开一轮 Gemini 重试。
用户取消则停止，不转交 GPT。插件不会额外启动一个 GPT 代理，接手由当前主智能体执行。

例如：

```json
{
  "title": "整理模型清单",
  "workspace": "/absolute/project",
  "instruction": "从提供的文本中提取名称并去重",
  "context": "...",
  "max_attempts": 3,
  "timeout_seconds": 300
}
```

兼容客户端也支持 `--max-attempts 3 --timeout 300 --attempt-timeout 60`。
升级后核对 `gemini_status.default_retry_policy`；旧 MCP 连接未刷新时使用新版兼容客户端。
